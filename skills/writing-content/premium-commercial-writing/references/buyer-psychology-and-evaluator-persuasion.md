# Buyer Psychology And Evaluator Persuasion

Parent skill: [`premium-commercial-writing`](../SKILL.md).

This original synthesis uses the supplied *The Bezos Letters*, *Yes!*, *Buyology*, and *The Adweek Copywriting Handbook* as durable concept inputs. It is not a reproduction of their text or examples. A proposal must persuade through relevance, proof, clarity, and reduced decision risk; psychological cues never replace procurement compliance or capability evidence.

## The evaluator journey

Model each section as:

`attention -> recognition -> relevance -> confidence -> risk resolution -> decision -> next action`

| Stage | Proposal job | Evidence or device |
|---|---|---|
| Attention | Earn reading time with the client’s actual situation | Specific, sourced problem statement |
| Recognition | Show that the proposer understands the mandate | ToR language, constraints, stakeholders, and consequences |
| Relevance | Connect the method to the client’s desired result | Outcome-linked workplan and assumptions |
| Confidence | Prove the team can deliver this work | Comparable evidence, role clarity, named deliverables |
| Risk resolution | Make failure, dependencies, and controls visible | QA, governance, escalation, safeguarding, and contingency |
| Decision | Make evaluation easy and auditable | Compliance matrix, scoring-aligned headings, price and terms |
| Next action | State what approval or clarification is needed | One specific decision request and handover |

## Book-informed operating rules

- **Test before scale:** where the proposal includes innovation, show a bounded pilot, learning question, acceptance threshold, and stop/rollback condition.
- **Customer obsession:** write to the client’s service users and institutional constraints, not only to the procuring organisation.
- **Simplify complexity:** give the evaluator an answer-first summary, then enough method detail to verify it.
- **High standards:** define quality gates, review roles, version control, and what “accepted” means.
- **Choice architecture:** present a small set of compliant options only when alternatives genuinely help the client decide; expose scope and trade-offs.
- **Social proof:** use only permissioned, verifiable references, outcomes, credentials, and named assignments. Never manufacture consensus or imply endorsement.
- **Authority:** lead with relevant evidence and method, not title-stacking.
- **Commitment:** make the client’s first step small and explicit, but never use a low-friction response to obscure a later obligation.
- **Context and memory:** repeat the client’s priority terms consistently, use stable visual cues, and connect each claim to its proof; do not use sensory or “neuro” language as a false assurance.
- **Copy sequence:** use a clear opening, mechanism, proof, objection/risk, and next step; do not turn a tender into a hype letter.

## Win-theme construction

Create three to five win themes. Each theme needs:

`client priority -> proposed response -> proof -> delivery control -> evaluator benefit`

Test each theme against the scoring criteria. If it has no client priority or proof, it is a slogan. If it has no delivery control, it is a promise. If it has no evaluator benefit, it is internal language.

## Ethical persuasion and compliance guardrails

- Never exploit fear, fatigue, urgency, status anxiety, or information asymmetry.
- Never hide exclusions, assumptions, subcontractors, conflicts, prices, or renewal terms.
- Never use scarcity unless the procurement or delivery constraint is real and documented.
- Never present a historical book finding as current science, procurement rule, platform rule, or client fact.
- Never copy a book’s distinctive wording, table, story, or sequence.
- If a claim is not in the source pack, label it `proposed`, `assumed`, or `NOT_ASSESSED`; do not strengthen it through adjectives.

## Proposal release test

- [ ] A named evaluator can find the answer to each criterion quickly.
- [ ] Each material claim has a source, credential, sample, or explicit evidence gap.
- [ ] Every promise has a mechanism, owner, dependency, and acceptance condition.
- [ ] Case studies distinguish verified outcomes from illustrative method.
- [ ] Options, price, scope, and trade-offs are transparent.
- [ ] The opening is client-led; the close asks for one clear decision.
- [ ] The argument remains persuasive when social proof, urgency, and adjectives are removed.
